# 豆包账号与视频接入开发规格

更新：2026-11-10。适用于本仓库当前版本。目标是在Toonflow设置中管理自有豆包账号，从视频节点点击一次后自动进入视频模式、上传参考图、填写完整提示词、提交并取回结果；登录、人机验证和新的费用或素材授权条件才需要本人处理。

## 实施依据与验收边界

已检查一个交付软件的账号与视频相关模块、主HTML及打包字节码：可借鉴账号档案、浏览器profile、账号服务、任务恢复的分层。该软件的明文凭据、自动同意付费提示、限流换号、重复补发和设备授权实现不复制进本仓库。实现独立编写，不依赖或分发其代码、安装包、授权信息及浏览器扩展。

已有项目实验证明：旧会话曾完成一次后台生成；官方网页本人提交后，可以后台查询和取回视频。新会话稳定自动提交、精确免费余额和无人工介入并未验收。源码分支存在不等于当前豆包服务可用。

本次开发授权包含文档、程序、必要验证与向用户仓库提交。实际视频生产、付费确认、验证码和账号登录仍由具体操作决定；开发过程中不自动消耗生成次数。

## 使用流程

1. 在“设置→豆包账号”添加账号，打开独立官方登录窗口，由本人完成登录。
2. 回到Toonflow保存登录并核对服务端身份。每账号使用独立profile；可改显示名称、选择默认账号、禁用或删除本地账号。
3. 一键配置内置“豆包本机视频”供应商；网关Key只保存在本机配置中，不写日志。
4. 视频节点选择Mini、15秒、9:16、720p与两张PNG，输入完整提示词，创建持久任务。
5. 新任务自动准备官方页面、Mini及15秒/9:16参数、两张参考图与完整提示词，核对实际请求后提交一次。不要求本人复制图片文字或逐条点击官方发送。官方只要求确认原参数且全部参数可严格核对时，自动同会话确认一次；不自动接受付费、素材责任或剧情修改。
6. 如需人机验证，本人处理。程序核对同一账号、实际文字和图片，不重放未知提交。
7. 找到本任务的实际视频对象后，使用官方无可见水印导出，下载校验后交给Toonflow保存。停止等待、重开页面或恢复任务不会创建第二条视频。

2.0.9按创作者最新明确要求改为自动提交。2.0.8及以前已建立的任务保留原执行方式，不将其静默升级为自动发送。账号免费余额仍未知，点击生成应基于该账号当前权益；不自动购买、充值或同意新增费用条件，也不把关键词“只用免费”称为上游计费保证。无人值守稳定性、精确扣次和真实生成回填须另行实测。

## 技术结构

- 沿用Bun、TypeScript、Express与现有单进程监听；不再安装Python后端或启动额外网关监听器。
- 业务模块放`apps/server/src/utils/doubao`，路由放`routes/doubao`；路由由现有生成器维护。
- 复用现有Chromium发现逻辑及已有Puppeteer依赖，启动程序自己拥有的独立可见浏览器，不接管日常浏览器或豆包客户端。
- SQLite保存账号元数据、冻结素材、任务、发送动作与结果归属；文件读写使用`@toonflow/file`。
- 首版Windows会话快照使用当前用户DPAPI保护；不支持的平台明确拒绝保存，不回退明文。
- 内置供应商放`packages/providers/src/media/doubaoLocalVideo.ts`；设置面板放`apps/web/src/components/settings/panels/doubao.vue`。
- 管理API沿用Toonflow页面请求授权；供应商API另用网关Key，限定回环请求。Key不创造或转移豆包权益。

## 账号与会话

账号使用随机内部ID与服务端身份摘要，显示名不参与归属。状态至少区分待登录、可用、待验证、禁用；精确剩余次数无法实读时返回未知。清本地标记不等于续期登录。

登录窗口由用户触发；保存时只访问官方身份接口，不发聊天或生成请求。Cookie、localStorage和浏览器真实用户代理来自该账号自己的浏览器，不生成伪造设备身份，不复制另一账号的请求模板。

profile按账号隔离。凭据在本机数据目录保存，API仅返回元数据。删除账号前检查未决任务；退出或禁用不删除已有视频。只关闭本程序拥有的浏览器进程，不杀端口上不明进程。

## 接口与鉴权

所有管理接口返回仓库统一`{code,data,message}`结构，并校验来源与`x-toonflow-workspace`。接口一文件、一方法，字段使用小驼峰。具体文件路径就是接口路径。

| 分组 | 能力 |
| --- | --- |
| `doubao/accounts` | 列表、新建、打开登录/验证窗口、保存官方会话、修改默认/启用状态、删除 |
| `doubao/jobs` | 本地任务列表、只读刷新、恢复原任务、提交前取消、打开原任务官方页面 |
| `doubao/configure` | 配置内置供应商和本机Key；重复配置保留其他供应商 |
| `doubao/gateway` | 模型、素材、创建任务、读取任务、已完成视频字节；要求Bearer Key |

素材只接受PNG，单图最多10MiB、1600万像素，两张普通参考图，保存字节SHA-256及顺序。路径由服务端生成，HTTP不接受任意本地路径、任意下载URL或Cookie导入。

创建任务必须有稳定`clientRequestId`和幂等键。同调用方相同操作号与相同意图返回同一任务；意图变化返回409。Key轮换不改变任务所有权。

## 任务状态与动作预算

主状态为：排队、准备、待登录、待官方确认、待验证、提交中、受理未知、等待实际任务、生成中、下载中、下载失败、完成、失败、取消。

收到聊天回复、HTTP200或流结束都不算视频生成成功。须从本任务绑定的会话、问题和实际视频标识确认；不能取账号最新视频。

- 初始生成动作最多一次，点击发送前及实际请求放行前分别落盘；重启不重放已操作发送的任务。
- 同会话内容恢复或普通参数续确认共享一次预算；不自动执行付费/素材声明/剧情变化确认。
- 受理未知只读对账，不换号、换模型、换ID或重新发送。
- 同账号最多一个未决生成；进程重启保留发送标记，未知任务不因租约超时放行。
- 只有发送前可以本地取消。取消HTTP等待不等于取消上游视频。
- 视频已生成时，重试仅限导出和下载。无官方无可见水印版本则保持未交付，不回退其他链接。

冻结内容包括完整原文、参考图字节与顺序、模型、时长、画幅、分辨率、账号和执行政策。核对真实请求文字块，不能只看输入框缓存；拒绝验证续发时丢失原文或图片的请求。

## Toonflow节点与恢复

视频节点在首次创建豆包任务前保存操作号。停止等待、组件重挂或恢复沿用此号；用户明确“重新生成”才创建新号。原任务没有结束时不允许用新号绕过未知状态。

操作号另存为工作区`assets/<节点ID>/doubaoOperation.json`，通过现有WorkspaceFiles原子创建、版本校验更新，发送前先完成保存，不依赖画布自动保存时机。结果路径在回填前记入此文件，崩溃后先恢复已有结果。准备失败但尚未操作发送时释放账号；用户下次点击原节点时，先查询确认原任务已失败或取消且没有发送动作，才建立新操作号。不后台自动重试。已发送、受理未知或已完成未取回的任务始终保留原号；“核对原任务后新建”仍保留作显式入口。此文件与节点素材一起备份，不直接修改画布JSON。

普通媒体供应商最终仍返回`MediaAsset[]`。适配器内部查询网关，用Key下载视频，返回`binary/Uint8Array`；不把Key放URL，也不让宿主无鉴权下载受保护URL。

待确认/待验证不当成媒体结果。节点与账号设置显示任务状态和恢复入口；真实生成完成后走宿主现有工作区保存与画布回填流程，不直接修改画布JSON。

## 文件交付与敏感数据

下载只接受官方已核验HTTPS媒体来源，视频标识必须匹配。限制重定向和大小，检查MP4头、非空、长度及摘要，以同目录临时文件原子发布，最大100MiB。实际测量和上游报告的时长/分辨率分别标注。

普通日志只记录本地任务号、阶段和安全错误码，不记录凭据、提示词正文、原始响应、验证详情或签名媒体URL。代码和Git提交不得包含真实账号、Cookie、Key、项目私密素材或交付软件提取文件。

## 开发顺序与验证

1. 账号存储、Windows保护、独立官方浏览器与身份核对。
2. 持久任务、幂等与状态机、素材冻结、官方提交观察及既有结果取回。
3. 受保护网关、内置供应商、设置面板与节点稳定操作号/恢复。
4. 生成路由，执行现有类型检查、构建和手动HTTP验证；使用隔离数据目录，不覆盖运行中的真实配置。
5. 检查提交文件中没有凭据、私密数据或提取代码，提交到用户仓库并核对远端提交。

遵守仓库不新增测试/模拟模块的要求。不以改名、临时mock或业务内自检绕过；手动验证覆盖未授权拒绝、非法输入、任务幂等、同账号未决冲突、重启保留、只读恢复及文件鉴权。构建通过与真实上游验收分开报告。

真实登录、验证码及一条正式视频验收需要用户参与；未做的项目明确标为未运行，不把它们写成已通过，也不把当前软件开发提交称为所有豆包账号可无人值守生成的证明。

## 关键接口契约

管理请求由同源页面携带`x-toonflow-workspace: 1`；网关请求携带`Authorization: Bearer <本机Key>`。所有请求还须来自本机回环地址。错误HTTP状态与响应`code`一致，业务错误码位于`data.code`；成功响应为200，创建账号/素材使用HTTP201，创建任务使用HTTP202，响应体成功`code`仍为200。视频内容接口成功直接返回MP4字节。

| 方法与相对路径（统一前缀`/api/doubao/`） | 主要字段与行为 |
| --- | --- |
| `GET accounts/list` | 返回平台支持情况、公开账号元数据、默认账号及未知余额 |
| `POST accounts/create` | `name`，1—80字；仅新建本地档案，不发送验证码 |
| `POST accounts/open` / `accounts/capture` | `id`；打开独立窗口／核对官方身份并保护会话 |
| `PUT accounts/update` | `id`及可选`name`、`enabled`、`isDefault` |
| `DELETE accounts/remove` | `id`；有未决生成时409，已下载视频保留 |
| `POST configure` | 返回实际服务端口对应的回环地址和本机Key；页面合并保存现有供应商配置 |
| `GET jobs/list` / `jobs/operation` | 最近200条本地任务／按`clientRequestId`查询绑定任务；不发送生成 |
| `POST jobs/open` / `jobs/refresh` | `id`；打开原页面／读取原任务 |
| `POST jobs/resume` | `id`、`stateVersion`、`mode: prepare/reconcile/download`；状态过期409 |
| `POST jobs/cancel` | `id`、`stateVersion`；只取消未发送任务 |
| `GET jobs/content` | `id`；页面鉴权读取已保存视频 |
| `POST gateway/asset` | `data`为原始PNG的base64，不接收URL；返回SHA-256素材ID及尺寸 |
| `POST gateway/create` | `clientRequestId`为UUID；可选`accountId`，及`model/prompt/duration/ratio/resolution/assetIds`；两张素材ID按顺序传入 |
| `GET gateway/task` / `gateway/content` | `id`；读原任务／用Key读取结果字节 |
| `GET gateway/models` | 当前Mini模型、默认账号与自动提交模式；余额为null |

省略`accountId`时，恢复请求优先使用原任务账号，其次才使用当前默认账号。更改默认账号不改变已有任务。重复保存同一个官方身份会被拒绝，避免同账号在不同档案重复并发。

## 恢复和故障处理

| 当前情况 | 允许动作 | 不执行的动作 |
| --- | --- | --- |
| 页面未切到视频入口、图片尚未准备 | 自动等待输入壳完成加载、切换视频模式并准备两图；准备失败且未发送则释放账号，显示具体失败阶段 | 未完成校验就发送或改写原文 |
| 登录过期／身份不符 | 恢复原账号、保存登录，再只读核对原任务 | 自动转移到其他账号 |
| 官方要求参数确认 | 仅在原文、两图与Mini参数可严格核对时，自动同会话确认一次；旧任务仍由本人处理 | 自动接受费用、素材责任或剧情变更 |
| 人机验证 | 本人处理后先只读核对；验证导致正文或图片缺失时停止 | 验证绕过、重放初始请求 |
| 发送后没有回执／服务重启 | 标记受理未知，保留原操作号和账号占用；从原会话恢复 | 超时后自动重投 |
| 视频生成中 | 绑定会话只读查询；有回执后每15秒查询，最长45分钟 | 查询到其他会话最新视频后冒充本任务 |
| 上游完成、下载失败 | “恢复下载”，仍取同一视频ID的官方导出 | 再生成一条或回退带可见水印版本 |
| 已完成 | 原节点继续取回，或在设置下载已有MP4 | 把HTTP200、文字回复或任务号当作视频 |

后台只读观察由已发生的任务动作触发，`createApp`不启动新监听或常驻调度器；服务重启后由显式恢复继续。停止节点等待不取消已提交上游任务。未知任务暂不提供“强制释放账号”入口。

## 已知范围与后续验收

当前只开放Windows、Mini、15秒、9:16、720p、两张普通PNG；Fast、任意时长/比例、首尾帧、音视频参考、账号自动轮换、精确余额、手机控制均未实现。官方网页可能只显示默认分辨率；实际请求必须仍为720p，否则本版阻止并提示不匹配，不擅自替换参数。网页结构、上传响应或官方协议变化时需要更新适配器。

源码接入完成不等于无人值守生产可用。正式验收顺序：本人添加账号并保存登录→默认账号或供应商固定账号→用已确认两图及完整提示词在画布点击生成→程序自动提交→如有验证亲自处理→回原节点取回→核对原文、两图、成片及实际扣次。结果未知时停留原任务，只读核对。2.0.9尚未运行真实视频生成回填的整条生产验收。

- 默认安装根目录：`%LOCALAPPDATA%\local.toonflow.doubaoTest\stable`；用户可在安装器中选择其他空目录。

- 测试版停用通用自动更新，避免测试功能被普通发布包覆盖。后续用新的测试安装包更新此测试版。
